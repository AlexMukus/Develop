# XAML / AXAML: разметка, ресурсы, стили, шаблоны

Общие правила для WPF и Avalonia. Отличия фреймворков — в wpf.md и avalonia.md.

## Содержание

- Форматирование разметки
- Привязки (Binding)
- Ресурсы и словари
- Стили
- Шаблоны (DataTemplate, ControlTemplate)
- Конвертеры
- Локализация

## Форматирование разметки

- Отступ — 4 пробела (или стиль проекта, если единообразен). Один уровень вложенности — один отступ.
- Не больше 3–4 атрибутов в строке; дальше — каждый атрибут с новой строки. Порядок: `x:Name`/`x:Key` → привязанные свойства → размеры/выравнивание → стиль/классы → обработчики.
- Пустые элементы — самозакрывающиеся (`<Border />`).
- Глубина вложенности разметки ≤ ~6 уровней. Глубже — выносить блоки в UserControl или упрощать сетку.
- Комментарии в разметке — только для нетривиальных решений («Grid нужен для оверлея прогресса»), не для очевидного.

## Привязки (Binding)

- Для свойств, которые UI не редактирует, — явно `Mode=OneWay` (снижает шум и защищает от случайной записи). Для ввода — `Mode=TwoWay` с осознанным `UpdateSourceTrigger` (для текстовых полей ввода обычно `PropertyChanged`, для паролей/дат — по задаче).
- Хрупкие привязки — с `FallbackValue` / `TargetNullValue`, чтобы UI не схлопывался при null.
- Пути привязок должны совпадать с именами свойств VM; опечатка в Path — молчаливая поломка. После переименования свойства VM — искать его имя по всему XAML.
- Не биндиться к свойствам, которых нет в VM, «на будущее».
- Сложные выражения в привязке (конкатенация, условия) — вынести в свойство VM или конвертер, не городить многословные StringFormat.

## Ресурсы и словари

Организация:

```
Themes/ (или Assets/)
├── Colors.xaml        # только цвета
├── Brushes.xaml       # кисти поверх цветов
├── Fonts.xaml
├── Converters.xaml
└── Styles/
    ├── Button.xaml
    └── TextBox.xaml
```

- Цвет используется только через кисть, кисть — только через цвет. Хекс-коды в разметке запрещены.
- Все словари подключены в `App.xaml`/`App.axaml` через MergedDictionaries — не подключать одни и те же словари в каждом окне.
- Ресурс — там, где область видимости: общий → App, частный → ресурсы окна/контрола.
- Ключи ресурсов: PascalCase со смысловым именем: `PrimaryBrush`, `DangerButtonStyle`, не `Style1`, `Red`.

## Стили

- Одинаковое оформление повторяющихся элементов — именованный стиль, а не копипаста атрибутов. Три и более повторения — точно стиль.
- Стиль-вариант наследуется: базовый `Button`-стиль → `PrimaryButtonStyle`/`DangerButtonStyle` через наследование (`BasedOn` в WPF, селекторы/`^` в Avalonia — см. avalonia.md).
- Не задавать в стилях то, что должно решать размещение (Margin конкретного экземпляра), и не задавать в разметке то, что должен решать стиль (цвета, шрифты).
- Не переопределять все свойства подряд «про запас» — стиль содержит только осознанные сеттеры.

## Шаблоны

- Соответствие VM → View: `DataTemplate` с `DataType` без ключа. Это основа навигации по типам (см. mvvm.md).
- `ControlTemplate` — только когда стилями не обойтись; внутри шаблона обязательны именованные части по соглашению `PART_...` (для кастомных контролов WPF).
- `ItemsControl` с нетривиальным элементом — выносить элемент в отдельный UserControl, если шаблон > ~30 строк.

## Конвертеры

- Один конвертер — одна задача, имя говорит о преобразовании: `BoolToVisibilityConverter`, `InverseBoolConverter`, `UnixTimeToLocalTimeConverter`.
- Общие конвертеры регистрируются в словаре конвертеров один раз; не объявлять новый экземпляр в ресурсах каждого окна.
- Конвертер — детерминирован и без состояния; никакого I/O и сервисов внутри.
- Частое преобразование с параметрами — лучше свойство в VM, чем пятый MultiBinding.

## Локализация

- Весь видимый пользователю текст — из ресурсов локализации (resx/ресурсные ключи), а не литералами в XAML и C#.
- Исключение: технические строки (имена классов в стилях, ключи, `x:Name`).
